# フェーズ1の未決事項についての判断

- 日付：2026-11-21
- 判断した人：オーナー
- 関係する issue：#1、#2、#6、#12、#13、#15、#16、#17、#18、#19、#21、#22、#24

フェーズ1のコーディングに入るために、未決事項をまとめて提案し、オーナーが答えた。下の A1〜F は、その一覧の番号。オーナーが変えたもの（A7、D6、E1、E2、E12）以外は、提案どおり。

## 判断内容

### A. 開発基盤とデータの型（#1、#2）

- A1. Node.js 24 LTS、pnpm 10、CI は GitHub Actions。
- A2. データの型（#2）の承認を待たずに、開発基盤（#1）を作り始めてよい。骨組みは中身が空の仮の型で作る。
- A3. CI で調べるのは、型チェック、lint、境界チェック（dependency-cruiser）、テスト。main への push と PR のたびに動かす。
- A4. お金は円単位の整数。通常の数値型（約9,000兆まで）で足りる。
- A5. フェーズ4向けの型は、入れ物だけ先に用意し、中身はあとで作る。
- A6. 最初から「ホールディングス1つ・事業会社1つ・業態1つ」として持つ。
- **A7（オーナーの変更）. コードは、適切にブランチを切り、PR をできるだけ細かく出す。** 細かくとは、必ずしも行数が少ないことではない（1つの PR が1つの目的・1つのまとまりになっていること、と読んでいる）。

### B. 週の進行と出店場所（#12、#13）

- B1. 1週間に操作できる回数に制限はつけない。
- B2. 純利益 ＝ 売上 − 食材費 − 人件費 − 家賃 − 減価償却費 − リース料 − 前金 − 違約金 − その他。
- B3. CF は、その週に実際に増減した現金。税金は入れない。
- B4. 立地ごとのカフェとの相性：駅前（オフィス街を含む）と商店街は良い、住宅地はふつう、郊外の大通り沿いはやや低い。値はマスターデータに置く。
- B5. 地図に一度に並ぶ物件は6件。
- B6. 物件は、入れ替わる前に押さえておくことはできない。

### C. 客、評判、価格（#15、#16）

- C1. 客層は分けず、フェーズ1は1つにまとめて計算する。
- C2. 季節や天気の波は入れない。
- C3. 乱数によるぶれは小さく（±5%ほど）。
- C4. 取りこぼした客の数を、店舗損益計算書の近くに見せる。
- C5. 満足度の内訳（料理、接客、値ごろ感、居心地）を見せる。
- C6. 価格は店全体で1つのつまみ。デフォルトを100%として、80〜130%を5%刻みで動かす。
- C7. メニューは飲み物2品と軽食2品。計算は「飲み物」と「軽食」の2つの区分で行う（設備が2種類のため）。
- C8. 食材の値段は時期で変わらない。
- C9. 価格を変えたときの見込みは、客数ともうけがどちらに動くか、向きだけを見せる。

### D. 店員と店長（#17）

- D1. 時給を決められる幅は、相場の80〜200%。
- D2. 士気は0〜100。時給を上げても、上がり方はだんだん鈍る。
- D3. 店長を解雇したときに士気が下がるのは、その店だけ。
- D4. 店長の能力は3つ（運営、接客の指導、人をまとめる力）。
- D5. フェーズ1では、店長が自分から辞めることは入れない。
- **D6（オーナーの変更）. 店長の給料も、店員の時給と同じく、プレイヤーが調整できる。**
- D7. フェーズ1では、店長の育成（お金を払って能力を上げる）は入れない。
- D8. 店員の人数と価格は、店ごとに「任せる」に切り替えられる。「任せる」にした項目は、店長が毎週自動で調整する。プレイヤーが手で変えると、その項目は「任せる」が外れる。

### E. 店舗損益計算書、競合、2店舗目（#18、#19、#21）

- **E1（オーナーの変更）. 呼び名は「店舗損益計算書」のまま。**
- **E2（オーナーの変更）. 店舗損益計算書は、PL と同じく、利益と費用に分けて書く。** 行の並びは `docs/design/overview.md` 1.4 の案。
- E3. 目安と比べた色づけを入れ、目安の数字も見せる。
- E4. 投資の出費と借入の返済は、店舗損益計算書には入れず、CF の側で見せる。
- E5. まず PC のブラウザ（横長の画面）を対象にする。
- E6. 競合 bot はカフェの会社が3社、1社あたり1〜2店。40週のあいだに出店か撤退が1〜2回起きる程度。
- E7. フェーズ1には、ほかの業態の bot は出さない。データの形は、あとで入れられるようにしておく。
- E8. bot は、性格ごとに決まったルールで動く。
- E9. 従業員の引き抜きと、難しさの設定は入れない。
- E10. 2店舗目を止める制約は、お金だけ。
- E11. 最初に持っているお金は、1つの額に固定する。
- **E12（オーナーの変更）. 借入はフェーズ1から入れる。ただし今は設計 issue を立てるだけにし、これから始める実装には入れない。**
- E13. フェーズ1でも倒産はありうる。現金がマイナスになったら警告を出し、4週の猶予のあいだに閉店や設備の売却で立て直せる。4週たってもマイナスのままなら倒産でゲームが終わる。

### F. 最初のコーディングのあとに回すもの

- 自動で進むモードとオフライン進行（#6）は、ボタンでの進行ができてから。
- チュートリアル（#22）は、ほかのフェーズ1の仕組みができてから詳しく決める。
- 新聞（#24）は、フェーズ1では短い記事だけにする（競合の開店・撤退・値下げ、自分の店の節目）。記事から出来事は起きない。詳しい設計は #24 で続ける。

## 理由

オーナーからの指示。変更した項目（A7、D6、E1、E2、E12）以外は、こちらの提案を採った。

## 確認が残っていること（この記録を書いた側の読み）

- D6：店長の給料を上げ下げしたときの効き方。店員の時給と同じく、店の士気が動き、幅は相場の80〜200%、と読んでいる。
- E2：PL の形として「売上高 → 売上原価（食材費）→ 売上総利益 → 販売費及び一般管理費 → 営業利益 → 特別損失 → 純利益」と読んでいる。前金をどこに置くか（販管費か、特別損失か）。
- E12 と E13：借入がフェーズ1に入ると、立て直しの手段に借入が加わる。最初の実装（借入なし）では、倒産の猶予のあいだの手段は閉店と設備の売却だけになる。
